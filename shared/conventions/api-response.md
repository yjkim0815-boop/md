# 📡 공통 API 응답 규격 (전 프로젝트)

> `happypointcard` 하위 **모든 프로젝트의 신규 API**가 따르는 공통 응답 표준.
> 프로젝트별 실제 코드/메시지는 각 프로젝트 문서에 두고, **규격 자체는 이 문서가 정본**이다.
>
> 🔒 **변경 규칙**: 아래 `code`·`detailCode` **대역/체계**를 바꾸는 것(대역 추가·remap·삭제)은 **임의로 하지 않고 사용자 확인 후** 반영한다.
> **예외(자동 OK)**: 개별 API 응답에 **detailCode/detailMessage 를 명시적으로 담아야 하는 경우**(레거시 rpsCd 등 그대로 전달)는 확인 없이 자동 추가한다.

## 1. 응답 엔벨로프
- **HTTP 는 항상 200.** 성공/실패는 body 의 `code` 로 판별한다.
- **성공**: `{ "code":"00", "message":"성공", "detailCode":"0000", "detailMessage":"성공", "result": { …결과데이터… } }`
  - 성공 시 `detailCode="0000"`/`detailMessage="성공"`을 **항상 세트로** 포함한다.
- **실패**: `{ "code", "message", "detailCode?", "detailMessage?", "result": {} }` (null 필드는 생략)
- **`result` 는 성공·실패 모두 항상 포함한다.** 데이터가 없으면 **빈 객체 `{}`** 로 내려보낸다(생략/`null` 금지).
- 성공 시 응답 래핑은 공통 advice(예: `ResponseBodyAdvice`)로 자동 처리 권장.

## 2. code 대역 (대분류, 2자리) — 해피앱 표준
| code | 의미 | 설명 |
|------|------|------|
| `00` | 정상 | 성공 |
| `01` | 이벤트(Rulebased) | 별도구성 |
| `40` | 시스템 인증 오류 | 로그인 필요/세션 만료/본인인증 미완료 |
| `41` | 시스템 인증 오류 | 권한 없음 |
| `50` | 정책적 제한 | 기간/자격/등급/횟수·한도/회원상태/약관동의/채널 등 |
| `60` | 제휴사 오류 | 제휴사(해피앱) 연동 |
| `70` | 외부 시스템 연동 | 외부 시스템 호출 실패 |
| `80` | 내부 시스템 연동 | 내부 시스템 호출 실패 |
| `91` | 파라미터 | 요청 파라미터 오류 |
| `92` | 토큰 | 토큰 오류 |
| `93` | 데이터처리 | 조회/검증/변환 등 데이터 처리 오류 |
| `99` | 기타 | 지정되지 않은 내부/미구현 |

- **인증**은 `40`(로그인/세션/본인인증) / `41`(권한). **정책·업무 규칙 제한**은 `50`.
- 대분류 code 는 **위 표로 고정**. 프로젝트가 임의 코드값을 새로 만들지 않는다.

### code ↔ detailCode 역할 (중요)
- **`code` (공통)**: **모든 프로젝트가 동일**하게 쓰는 대분류 응답코드(위 표). "무슨 종류의 결과/오류인가".
- **`detailCode` (서비스별)**: **같은 종류의 오류라도 서비스(엔드포인트)마다 다른 4자리**를 부여한다. → "그 오류가 **어느 서비스에서** 발생했는가"까지 식별 가능.
  - 예: "파라미터 누락"이라는 동일 오류여도, A서비스는 `9111`, B서비스는 `9121`처럼 **서로 다른 detailCode**로 관리 → 로그/모니터링에서 발생 위치 추적.
  - 즉 `code` = 공통 응답 / `detailCode` = 그 공통 응답에 **서비스별 식별코드를 덧붙여** 관리.
- `detailCode`/`detailMessage` **실제 값·부여 체계는 프로젝트별로 정의** → 각 프로젝트 [api-detail-response.md](../../projects/ha-web-api/api-detail-response.md). (성공 시엔 항상 `0000`/`성공`)

## 3. 원칙
- **기존 비즈니스 로직·응답코드 보존**: 레거시 rpsCd/rpsDtlCd/메시지는 원형 그대로 전달, remap·창작 금지. → [spring.md](./spring.md) "기존 비즈니스 로직·응답코드 보존"
- **내부정보 노출 금지**: 예외 스택/SQL/경로는 서버 로그만. 클라이언트엔 일반 메시지(`code=99`).
- **프론트 판별**: HTTP 200 고정이므로 `body.code === "00"` 이면 성공, 그 외 실패.

## 4. 문서 분리 규칙
- **이 문서(공통)**: 엔벨로프 + code/message 대분류(00~99).
- **각 프로젝트 `api-detail-response.md`**: 그 프로젝트의 **detailCode/detailMessage 정의·실제 값**, 도메인별 message, 레거시 rpsCd 매핑 등 구체 카탈로그.
