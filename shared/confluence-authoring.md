## 2. 톤 규칙

### 2-1. 실측 > 추정
추정치를 쓰고 있더라도 **전수분석·실측 자료가 있으면 즉시 교체**한다.
> 사례: KB 추정 "월 36~62건" → 성과 요약 실측 "248건 중 181건, 72.9%" 로 교체. 설득력이 비교가 안 된다.

### 2-2. 과잉 약속 금지
- **안 되는 것을 명시**한다. 두루뭉술하게 넘기면 다음 달에 신뢰를 잃는다.
- 미확정 일정은 **"~할 계획입니다"**, 확정은 **"~합니다"** 로 구분한다.
- "곧 됩니다"는 쓰지 않는다. **단계 번호**로 표기한다(2단계·3단계).

### 2-3. 독자 언어로 쓴다
- 독자가 개발자가 아니면 **내부 용어를 전부 제거**한다(테이블명·class 규칙·API·JSP 등).
- 제거가 아니라 **번역**한다: `Rule` → 참여 조건 / `프로모션폼` → 양식 / `META_JSON` → 리워드 설정
- 남는 용어는 **부록 용어표**에 5~7개만.

### 2-4. 내부 지표는 선별한다
같은 데이터라도 **독자에 따라 역효과**가 난다.
> 사례: "개발비 월 303만원 절감"은 경영 보고에는 핵심이지만, 실무자 대상에서는 *"우리한테 일 떠넘기냐"* 로 읽힌다. → **"월 30건이 대기 없이 진행 = 기획한 날 바로 오픈"** 으로 독자 이득으로 번역.

### 2-5. 반발 지점을 선제 대응한다
독자가 반발할 지점을 미리 찾아 **인정 → 대안 → 이득** 순으로 배치한다.
> 사례(이미지 3분할): ① *"이건 담당자 업무가 아닙니다"*(인정) → ② 디자인 규격·도구 제공(대안) → ③ 버튼만 교체하면 되는 이점(이득).
> ⚠️ **③을 먼저 꺼내면 변명으로 들린다.** 순서가 중요하다.

### 2-6. 제약은 "언제 되는지"와 함께
"지원되지 않습니다" ❌ → **"몇 단계에 제공 예정입니다"** ⭕
절 제목도 *"아직 지원되지 않는 것"* 보다 **"지금은 협의가 필요한 것"** 이 낫다.

## 3. Confluence 작성 규약 (MCP HTML)

### 3-1. 요소 사용 기준
| 요소 | 용도 |
|---|---|
| `panel-info` | 배경 설명·부연 |
| `panel-success` | 핵심 메시지·이득 |
| `panel-warning` | 한계·주의 |
| `panel-error` | 금지 사항 |
| `panel-note` | 참고·보조 |
| `status` (green/yellow/red/blue/neutral) | 상태 표기 — 가능/협의/불가/확장/계획 |
| `task-list` | 준비 사항 체크박스 |
| 표 | **본문 대부분은 표로**. 산문보다 스캔이 쉽다 |

### 3-2. 🎨 표 스타일 규약 (⚠️ 사용자 확정 · 2026-08-04)

> **모든 표에 아래 규격을 적용한다.** 사용자가 직접 편집한 스타일이며, 이후 작성하는 모든 Confluence 표는 이 형태를 따른다.

| 항목 | 규격 |
|---|---|
| **표 폭** | **`data-layout="full-width"`** — 좌우 100% 폭(반응형). ⚠️ `data-width`(고정 px) 사용 금지 |
| **헤더 옵션** | **사용하지 않는다.** `<thead>` · `<th>` 금지 → **전부 `<tbody>` + `<td>`** |
| **헤더 배경** | **`#deebff`** (밝은 파랑) — `data-background="#deebff"` + `style="background-color: #deebff"` **병기** |
| **헤더 정렬** | **모든 헤더 셀은 가운데 정렬** — `<p style="text-align: center">` (가로형·세로형 공통) |
| **열 너비** | `data-colwidth` 를 **내용 성격에 맞춰 비율 배분**한다. 총합 **1226** 기준 (§3-2-1) |

**작성 예 — 가로형 헤더**
```html
<table data-layout="full-width"><tbody>
  <tr>
    <td data-background="#deebff" data-colwidth="260" style="background-color: #deebff">
      <p style="text-align: center">구분</p></td>
    <td data-background="#deebff" data-colwidth="966" style="background-color: #deebff">
      <p style="text-align: center">내용</p></td>
  </tr>
  <tr><td data-colwidth="260"><p>값1</p></td><td data-colwidth="966"><p>값2</p></td></tr>
</tbody></table>
```

**작성 예 — 세로형 헤더(라벨 표)**
```html
<table data-layout="full-width"><tbody>
  <tr>
    <td data-background="#deebff" data-colwidth="200" style="background-color: #deebff">
      <p style="text-align: center">일시</p></td>
    <td data-colwidth="1026"><p>내용</p></td>
  </tr>
</tbody></table>
```

#### 3-2-1. 열 너비 배분 기준
`data-colwidth` 를 **모든 셀(헤더·본문 전부)** 에 지정하고, 총합을 **1226** 으로 맞춘다.

| 표 성격 | 배분 원칙 | 예 |
|---|---|---|
| **라벨 표**(세로형 헤더) | 라벨 최소, 내용 최대 | `200 / 1026` |
| **대비표**(좌우 비교) | **균등 분할** — 한쪽이 넓으면 시선이 쏠린다 | `260 / 483 / 483` |
| **설명 중심** | 설명 열을 최대로 | `200 / 866 / 160` |
| **짧은 값 열**(단계·소요·상태) | 최소폭 | `160` ~ `326` |

> ⚠️ **`data-width`(고정 px)는 쓰지 않는다.** `data-layout="full-width"` + `data-colwidth` 조합이 화면 폭에 맞춰 비율로 늘어난다.

> ⚠️ **`<th>` 를 쓰면 Confluence 표 옵션(헤더 행/헤더 열)이 켜진 상태가 된다.** 사용자는 이 옵션을 모두 해제하고 **배경색으로 헤더를 표현**하는 방식을 쓴다.
> ⚠️ `status` 요소는 `data-status-style="bold"` 를 함께 준다.

### 3-3. ADF 중첩 제약 (위반 시 API 거부)
- **panel 안에 표·expand·blockquote·panel 금지** → 패널은 문단·목록만
- 리스트 항목 안에 heading·표·panel·expand 금지
- task/decision item, heading, caption은 **인라인 전용**
- 표 셀에는 heading·panel·목록 가능, **중첩 표는 불가**

### 3-4. ID 규칙
- `data-user-id` · `data-id` · `data-collection` · `data-local-id` 등 **불투명 ID는 절대 지어내지 않는다.** 기존 내용이나 도구 출력에서 복사한 것만 사용
- 신규 노드에는 `data-local-id`를 넣지 않는다
- 네이티브 매크로는 `data-extension-type="com.atlassian.confluence.macro.core"`, 스토리지 XML(`<ac:structured-macro>`) 금지

## 4. 자리표시자·초안 원칙

### 4-1. 모르는 값은 채우지 않는다
확정되지 않은 값(일시·담당 부서·연락처·링크)은 **`<span data-type="placeholder">항목명</span>`** 으로 비워둔다.
> 그럴듯하게 지어 넣으면 그대로 배포된다. **비워두고 보고**하는 것이 원칙.

### 4-2. 초안은 초안으로
- `status: "draft"` 로 유지한다. **발행은 사용자만 결정**한다.
- 사용자가 브라우저에서 같은 초안을 열어두면 **자동저장 충돌** 위험 → 작성 전 닫도록 안내

### 4-3. 이미지
- **첨부 업로드 도구가 없다.** 이미지는 직접 넣을 수 없다.
- → 본문에 **`① 여기에 [화면명] 캡처`** 자리표시자를 배치하고, 사용자가 드래그앤드롭하도록 안내
- 캡처 요청 시 **개인정보·크리덴셜 마스킹**을 함께 안내한다

### 4-4. 기재 금지
- **비밀번호·토큰·키·DB 접속정보** — 어떤 경우에도
- 실제 회원 정보·연락처가 담긴 캡처
- 미공개 소재를 외부 서비스에 업로드하도록 유도하는 안내

## 5. 작성 후 보고 형식

작성·수정 후에는 반드시 아래를 사용자에게 알린다.
1. **무엇을 바꿨는지** (섹션별)
2. **왜 그렇게 판단했는지** — 특히 넣지 않기로 한 것과 그 이유
3. **비워둔 자리 목록**
4. **확인이 필요한 항목** — 사실관계가 불확실해 추정으로 채운 부분

## 6. 📎 문서 연동 구조 (Confluence ↔ Jira ↔ KB)

> 📌 **2026-08-04 방향 확정.** Jira 세부 작성 규격은 별도 문서(`jira-authoring.md`)로 추후 수립하며, 여기서는 **연동 구조**만 정의한다.

### 6-1. 기본 단위 — 개발 1건 = 컨플 1 + 지라 1

```
개발 건 1개
 ├─ Confluence 1 페이지   ← 설계·배경·결정·산출물 (읽는 문서)
 └─ Jira 1 이슈          ← 진행·상태·담당·일정 (움직이는 티켓)
        ↕ 링크로 상호 연결
```

- **연동 방식은 "링크"** 다. 내용을 양쪽에 복사하지 않는다(KB의 *"정본 1곳 + 포인터"* 원칙과 동일).
- Jira 이슈 → Confluence 페이지 링크, Confluence 페이지 → Jira 이슈 링크 **양방향**으로 건다.

### 6-2. 규모별 확장

| 규모 | Confluence | Jira | 비고 |
|---|---|---|---|
| **개발 1건** | 1 페이지 | 1 이슈 | **기본 단위** |
| **프로젝트** | **N 페이지** | **N 이슈** | 상위 페이지(허브) + 하위 페이지 구조 |
| **대형 프로젝트** | N 페이지 | N 이슈 | **필터로 묶어 플랜(Plan) 생성** — 로드맵·일정 관리 |

> 프로젝트가 커지면 **Jira 필터 → 플랜** 계층이 하나 더 붙는다. Confluence는 **허브 페이지**가 그 역할을 한다.

### 6-3. KB 연동 (3자 추적)

```
Jira 이슈 ── 이슈키 ──> KB 문서(프론트매터) <── 링크 ── Confluence 페이지
```

- KB 문서 프론트매터의 **`이슈키:`** 에 Jira 키를 기록한다 → `grep 이슈키` 로 크로스 검색.
- 각 프로젝트/태스크 **`INDEX.md` 문서목록**에 Confluence·Jira 링크를 1줄씩 등록한다.
- ⚠️ **사내 과제코드와 Jira 키를 구분해 적는다.**
  - 사내 과제코드: `HA25H101` · `HA26H197` (Jira 아님)
  - Jira 키: `WORK-7213` · `YAWJ-225`
  - 예: `이슈키: HA26H197 (과제) · WORK-7213 [YAWJ-225] (Jira)`

### 6-4. 이력 관리
- Confluence·Jira 문서는 **해당 프로젝트/태스크 `INDEX.md` 문서목록에 링크 1줄**로 등록한다.
- 프로젝트·태스크에 귀속되지 않으면 **[`projects/etc/`](../projects/etc/INDEX.md)** 에 기록하고 나중에 배정한다.
- 성향·작업 방식의 변화는 `personal/tendency/` · `projects/<slug>/tendency/` 에 기록한다(운영 규칙 준수).

### 6-5. ⏳ 추후 수립 — `shared/jira-authoring.md`
Jira 작성 규격은 별도 문서로 만든다. 착수 시 아래를 포함한다.
- **생성 전 필수 절차** — `getJiraProjectIssueTypesMetadata` 로 프로젝트·이슈유형별 **필수 필드 선조회**(추측 생성 금지)
- 요약(제목) 규칙 · 이슈유형별 설명 템플릿(버그·개발·인프라요청 등)
- 표·패널은 **본 문서 §3-2 스타일 규약을 그대로 재사용**(동일 ADF)
- 🔴 **안전 규칙** — 이슈 생성·상태 전이·담당자 지정은 **사용자 승인 후**. Confluence의 "초안 유지"에 대응하는 장치가 Jira에는 없다(생성 즉시 실재 + 알림 발송)
- 서비스데스크 프로젝트(`GIFT`·`HPMKT`·`BUHPAPP`)는 **고객 대면**이라 별도 취급
