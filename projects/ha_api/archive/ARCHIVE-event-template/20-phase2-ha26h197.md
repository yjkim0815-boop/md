# 📗 2차 상세 — `HA26H197` Step2 프로모션폼 기능 (2026 상반기)

> 출처: `20260728_HA26H197_Step2_프로모션폼_RuleBased_완료보고_영구아카이브.md` (2차 최종 정본)
> 클래스 바인딩(Rule Based 컴포넌트)은 분량이 커서 별도 → [21-class-binding-spec.md](./21-class-binding-spec.md)

## 1. 기능 목적
이벤트 상세 화면에서 운영자가 **재사용 가능한 프로모션폼을 선택**하고, 해당 폼을 **현재 이벤트에 연결**할 수 있도록 제공.

**핵심 목적**
- 이벤트 화면 구성 **표준화**
- 반복 JSP 개발 **공수 절감**
- **유형별 프로모션폼 재사용**
- 운영자 **선택 편의성 개선**
- **Rule Based 실행 구조와 연결**

## 2. 주요 기능

### 2-1. 프로모션폼 선택
- 등록된 프로모션폼 **목록 조회**
- **카드형 UI**
- 폼명 / 설명 표시
- **유형 뱃지** 표시 (→ Label 기능, §5)
- **미리보기 이미지** 표시
- 선택 버튼 제공

### 2-2. 프로모션폼 연결
```text
EVENT
→ EVENT_TMPL_BRIDGE   (EVENT_SEQ + FORM_SEQ 연결, PROMOTION_YN 사용여부)
→ EVENT_TMPL_FORM     (프로모션폼 마스터)
```

### 2-3. 프로모션폼 임시 HTML
```text
EVENT
→ EVENT_TMPL_FORM_HIST
```
> ⚠️ **`EVENT_TMPL_FORM_HIST` 는 명칭과 달리 이력 누적용이 아니라, 페이지 빌더 작업 중 HTML 임시 저장용 테이블이다.** (리스크 항목 → [71](./71-risks-followups.md))

## 3. 프로모션폼 유형

**대표 유형 (구현)**
- 쿠폰
- 포인트
- 응모
- 클릭

**확장 가능 유형 (후보)**
퀴즈 · 투표 · 난수 입력 · 출석 · 스탬프 · 룰렛 · 댓글 · 설문

## 4. 미리보기 이미지
프로모션폼 선택 화면의 **기본 미리보기 이미지 4종**:

| 유형 | 이미지 파일 |
|------|-------------|
| 쿠폰 발급 | `default_preview_coupon_issue.png` |
| 포인트 지급 | `default_preview_point_issue.png` |
| 응모 적재 | `default_preview_entry_save.png` |
| 클릭 적재 | `default_preview_click_save.png` |

- 경로: `https://front.happypointcard.com/ha/resources/api/images_renewal/event/`
- DB 저장: `EVENT_TMPL_FORM.PREVIEW_IMG_URL` (VARCHAR2 1000)

## 5. Label 기능 (유형 뱃지)

> **상태: KEEP** — 2차 완료보고서와 **분리 관리**. 후속 필요 시 독립 결과보고서로 재사용.

**목적**
- 이벤트 유형 식별 / 프로모션폼 유형 뱃지
- 쿠폰 · 포인트 · 응모 · 클릭 **분류**
- **검색 / 필터 확장**
- 이벤트 **복사·재사용**
- 운영자 편의성 향상

**데이터 연결**: `EVENT_TMPL_FORM.FORM_TYPE_NM`
**화면 표시**: `[쿠폰]` `[포인트]` `[응모]` `[클릭]`

> 📌 이 Label 기능은 `HA25H204` 로드맵의 **1차 단계**에 해당 → [11](./11-roadmap-ha25h204.md)

## 6. 역할 분리 구조
```text
프로모션폼                    Rule Based                    공통 JavaScript

- CTA/Submit/Input 요소       - 쿠폰/포인트/응모/클릭 Rule    - class 파싱
```

## 9. 핵심 결과보고 확정 문구
> 관리자가 프로모션폼 내 CTA 버튼 또는 Submit 버튼에 Rule을 바인딩하여, 사용자가 해당 버튼을 클릭했을 때 연결된 Rule이 실행되도록 설정한다.

> Rule Based 컴포넌트 연동을 통해 프로모션폼 내 CTA 버튼, Submit 버튼, 입력 컴포넌트와 Rule 실행 구조를 표준 class 기반으로 연결할 수 있게 되었다.

> 공통 JavaScript가 `ha-btn-{slotNo}-{role}` class를 파싱하고, slotNo와 role을 기준으로 입력값을 수집한 뒤 연결된 Rule을 실행한다.
