## 7. TO-BE 기능 설계 (착수보고 3~4p 기능표)

| 구분 | 기능 | 효과 |
|------|------|------|
| ADMIN | **DOM 등록관리 (HTML, JS, CSS)** | BO 웹 디자인 컴포넌트 제공, 프로모션 유형별 기본 템플릿 제공 |

| ADMIN | **템플릿 제공** | 단순 버튼 / 퀴즈 입력 / 출석체크(스탬프형) → 퍼블리싱 시간 단축 |

## 10. 1차에서 설계된 테이블
> 개발DOC에 DDL 첨부. 모두 스키마 `SPCADMIN`. **2차 `EVENT_TMPL_*` 체계의 기반.**

| 테이블 | PK | 용도 |
|--------|----|------|
| `EVENT_TMPL_CONTENTS` | `EVENT_SEQ`+`CONTENTS_TYPE` | 템플릿 마크업 본체. `CONTENTS_TYPE` = **HTML / CSS / JS**, CLOB |
| `EVENT_TMPL_CONTENTS_HIST` | idx(`EVENT_SEQ`,`PROFILE`) | 발행 이력·롤백 근거. `PROFILE` = **PROD / STAGE / DEV**, `CONTENTS_TYPE` = **VIEW / PROC** |
| `EVENT_TMPL_ASSETS` | `EVENT_SEQ`+`ASSET_FILE_NM` | 리소스(이미지) 관리 |
| `EVENT_TMPL_TESTER` | `MBR_NO` | 테스터. `TESTER_TYPE` = **100 개발자 / 200 담당자 / 300 관계자** |
| `EVENT_TMPL_TESTER_SEQ` | `MBR_NO`+`EVENT_SEQ` | 테스터↔이벤트 매핑 |
| `EVENT_PROC_BRG` | UNIQUE idx | `EVENT_SEQ`, `BRIDGE_TYPE`, `BRIDGE_SEQ`, `ISUE_TYPE` — **이벤트 간 연계(브리지), 2025-05-14 추가** |

→ DDL 전문: [30-ddl-event-tmpl.md](./30-ddl-event-tmpl.md) · [31-ddl-event-proc.md](./31-ddl-event-proc.md)
