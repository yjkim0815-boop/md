## 2. `FUNC_ID` 체이닝 (핵심 메커니즘)

**하나의 `RULE_ID` 가 `ORDER_NUM` 순서로 여러 `FUNC_ID` 를 실행**한다. PK가 `RULE_ID`+`ORDER_NUM` 인 이유.

| RULE_ID | 체인 |
|---------|------|
| `RULE-022` | ① `FN-407` 난수입력 검증 → ② `FN-001` CMS쿠폰 발급 |
| `RULE-402` | ① `FN-404` 신규회원 체크(기간) → ② `FN-001` CMS쿠폰 발급 |
| `RULE-412` | ① `FN-403` 신규회원 체크(당일) → ② `FN-001` CMS쿠폰 발급 |
| `RULE-561` | ① `FN-601` 투표 처리 → ② `FN-001` CMS쿠폰 발급 |

> 💡 패턴: **[선행 조건/참여 처리] → [리워드 발급]**. `FN-001`(CMS쿠폰발급)이 **공통 종단 함수**로 재사용된다.

## 3. `FUNC_ID` 대역 체계

| 대역 | 기능군 |
|------|--------|
| `FN-001` ~ `FN-004` | **CMS쿠폰 발급** (조건별) |
| `FN-011` | 쿠폰받기(가상쿠폰) 발급 |
| `FN-101` ~ `FN-104` | **포인트 발급** (조건별) |
| `FN-201` ~ `FN-202` | **제휴쿠폰** 발급 / 난수 제휴쿠폰 |
| `FN-301` ~ `FN-304` | **응모 적재** (조건별) |
| `FN-321` | **클릭 적재** |
| `FN-403` ~ `FN-404` | **신규회원 체크** (당일 / 기간) |
| `FN-407` | **난수입력** 검증 |
| `FN-601` | **투표** 처리 |

## 4. `BUTTON_TYPE` 코드 체계 (3자리)

`R` + [기능군] + [순차]

| 접두 | 기능군 | 코드 예 |
|------|--------|---------|
| `RC*` | 쿠폰(CMS·가상) | `RCA` `RCB` `RCC` `RCD` `RCE` `RCF` `RCG` `RCH` `RCI` |
| `RP*` | 포인트 | `RPA` `RPB` `RPC` `RPD` |
| `RA*` | 제휴쿠폰 | `RAA` `RAB` |
| `RL*` | 응모·클릭(적재) | `RLA` `RLB` `RLC` `RLD` `RLE` |
| `RN*` | 신규회원 | `RNA` `RNB` `RNC` `RND` `RNE` `RNF` |

> ⚠️ **체인의 각 단계마다 별도 `BUTTON_TYPE` 이 부여**된다(예: `RULE-022` → `RCF`, `RCG`). 즉 `BUTTON_TYPE`은 룰 단위가 아니라 **실행 단계 단위** 식별자.
> ⚠️ 2차(`EVENT_TMPL_RULE`)에는 `BUTTON_TYPE` 이 없다 — **class `role`** 이 그 역할을 대체 → [21](./21-class-binding-spec.md)

## 5. 조건(허들) 유형

| 허들 | 의미 |
|------|------|
| **기간 내 1회** | 이벤트 전체 기간 중 1회만 |
| **1일 1회** | 하루 1회 (일자 리셋) |
| **날짜지정** | 특정 날짜에만 가능 (위 허들과 조합) |
| **무제한** | 제한 없음 (클릭 적재 전용) |
| **기간 내 가입여부 / 당일 가입여부** | 신규회원 체크 전용 |

→ 2차 `META_JSON.cond`(`type`/`pCnt`/`dCnt`)로 일반화됨 → [33](./33-meta-json-spec.md)

## 6. `RULE_KEYWORD` 검색 규약
- 형식: **파이프(`|`) 구분** — 예 `제휴쿠폰|기간내1회`, `CMS쿠폰|기간내1회|난수`
- 용도: **BO 룰 검색·선택 UI** 필터링
- 조합 순서 관례: `[기능] | [허들] | [부가조건]`

## 7. 2차 Rule 유형 (확장 후보 포함)
2차 `EVENT_TMPL_RULE` 기준 Rule 마스터 대상:
**쿠폰 발급 · 포인트 지급 · 응모 적재 · 클릭 적재** (구현) + **퀴즈 · 투표 · 난수 · 출석** 등 (확장)
