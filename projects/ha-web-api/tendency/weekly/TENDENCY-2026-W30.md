# 🧭 ha-web-api 성향 — 2026-W30

> **용도**: 새 요청 시 **최근 3개월 프로젝트 성향을 먼저 읽고** 반영.

## 1. 이 주기의 주요 관심/작업 영역
- **인프라**: 스테이징 Tomcat 10.1.57 커스텀(포트/호스트/DB/프로파일), Scouter APM 연동, JDK21 격리, 편의 알리어스.
- **프론트 이관 설계**: JSP(ModelAndView) → Next.js(happypoint-web2). 페이지 URL↔API 매핑(엑셀 118행), 인터페이스(계약) 단위 파일화 구상.
- **컨벤션/문서**: ECC 참조로 java/spring/sql 컨벤션 고도화, md 저장소 지속 현행화.

## 2. 관찰된 작업 성향
- **의사결정**: 되돌리기 어려운 작업(덮어쓰기, 포트, 경로)은 **먼저 확인** 후 진행. 애매하면 옵션 제시 선호.
- **문서화**: **"묻지 말고 수시로 현행화"** → md 자동 갱신 기대.
- **안전장치**: 덮어쓰기 전 백업, dev 정본 보존 확인, 검증 TODO 명시.
- **경로 민감**: 로컬 vs 서버 반영 대상을 정확히 구분해 안내받길 원함.
- **소통**: 짧고 직접적, 근거·예시·표 선호, 반복 확인 질문.
- **작업 리듬**: 한 단계 하고 결과 보고 다음 요청, 실서버 바로 검증.

## 3. 적용법 (Actionable)
- md 변경은 즉시 현행화 후 요약 보고.
- 인프라/파일 덮어쓰기 전 백업 + 변경점 표.
- 로컬/서버 구분 후 서버 반영 경로·명령까지 제공.
- 리스크(JDK21×에이전트, 포트 충돌)는 검증 TODO로 분리.

## 4. 특이/주의
- 폴더 `j-ha-web-api` → 저장소명 `ha-web-api`(경로 참조 주의).
- DB 비번 평문(ROOT.xml)·톰캣 폴더 git 커밋 금지.
